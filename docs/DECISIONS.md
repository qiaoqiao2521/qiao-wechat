# 关键决策

基线：2026-09-07；2026-09-14 实施轮更新。区分「现有约定」「本次建议」「已采用（本轮实施）」。

| ID / 状态 | 决定 | 原因与未选方案 | 重访条件 |
|---|---|---|---|
| D01 现有约定 | Python + FastAPI + SQLAlchemy | 复用现有工具链；不照搬 wxAiPost 的 Go/Vue/MySQL 全栈 | 实际部署或吞吐证据证明现栈无法满足 |
| D02 现有约定 | 本仓负责排版投递，上游负责内容和个人 IP 流程 | 内容仓有独立所有权；不把本仓变成总路由器 | 用户明确改变产品职责 |
| D03 现有约定 | Markdown 和 HTML 共用投递服务 | HTML 由外部系统完成视觉设计，重渲染会破坏意图；不复制第二条上传链 | 入口协议出现无法兼容的明确需求 |
| D04 现有约定 | 默认草稿箱交付，手机预览/发布显式关闭 | OPS 已有账号权限受限的历史记录；不以「个人认证」等标签推定接口权限 | 对目标账号有新权限证据及对应授权 |
| D05 现有约定 | XHS 采用导出包 | 与当前平台接入范围一致；不扩展为自动运营系统 | 用户提出明确新需求 |
| D06 本次建议 | 先证明安装、状态与恢复，再扩大后台 | 已有 API 和工具页可以承载闭环；不把重写 UI 当作可靠性修复 | 多次真实操作证据表明当前界面妨碍工作 |
| D07 本次建议 | 保留现有调度器边界，暂不加 Celery/RQ | 当前默认草稿模式尚未证明持久定时发布需求；先修小范围实际缺口 | 真实需要跨重启/多 worker 任务，并有明确验收案例 |
| D08 本次建议 | 远端结果不确定单独表达，不自动盲重发 | 微信请求与本地事务不能原子提交；素材去重不等于文章幂等 | 上游提供可验证的幂等或查询对账能力 |
| D09 本次建议 | WCM_ 与已有命令维持兼容 | 命名收尾不应破坏现有部署；禁止全局替换所有旧字符串 | 有版本迁移、兼容期与恢复方案 |
| D10 已采用 | 草稿幂等键 = sha256(账号 + 动作 + 内容修订)，内容修订 = 渲染/替换前的稳定输入哈希，存 `publish_jobs.request_key` | 内容派生键天然区分修订；不新增表；不做跨进程分布式锁（进程内 per-key 锁 + 持久键兜底）。未选：请求头 Idempotency-Key（要求调用方管理键）| 出现多进程部署或调用方要求自带键 |
| D11 已采用 | 未知结果用 `error_category=remote_result_unknown` + `article.meta.draft_outcome=unknown` 表达，不新增枚举值 | 避免 SQLite 枚举 CHECK 约束重建式迁移；普通 String 列 + JSON meta 只需 ADD COLUMN。未选：ArticleStatus 加 `draft_unknown`（旧库需表重建）| 需要按状态做复杂查询或迁移到非 SQLite |
| D12 已采用 | 失败/成功记录在服务内即时 commit（commit 失败再用独立会话兜底），外层事务只承担后续步骤 | 复现证明：外层回滚会连同 article 行一起抹掉尝试记录。未选：仅依赖外层 commit（被测试否定）| 出现需要多步骤严格原子回滚的业务 |
| D13 已采用 | HTML 入口的 `<head><style>` 规则按选择器内联到元素 style；`<style>` 标签本身移除 | 微信不支持 style 标签；直接取 body 会静默丢弃上游类样式。未选：仅文档声明"必须内联样式"（把负担推给上游）| 出现 CSS 特异性冲突误覆盖的真实案例 |
| D14 已采用 | 主题代码块统一 `white-space: pre-wrap; word-break: break-all` | 微信端无横向滚动，`overflow-x:auto` + `pre` 会导致长代码行被裁剪（375px 实测）。未选：保留横向滚动（预览可滚、微信失效）| 微信编辑器支持横向滚动代码块 |
| D15 已采用 | 定位取舍（2026-09-14 用户确认）：wxAiPost 类 Go/Vue 项目只作发布链路与后台结构参考；排版层方向为 WeMD / xiaohu-wechat-format（主题 CSS 即数据，不搬 TypeScript 引擎）；外部重做版 Python 源码包（wx_content_mesh_python.zip）不再导入——其架构已被本仓实现并超越（多 audit_logs、幂等/unknown 可靠性层、13 主题、71 项测试）| 重做会丢弃已验证的排版核心与可靠性回归；主题是 CSS 数据，可从 TS 生态移植主题而不移植引擎 | 本仓出现无法承载的新需求，且外部包有实证优势 |
| D16 已采用 | 2026-09-14 缺口补齐（除插件系统外）：预览内置深色模拟切换（反相+色相旋转近似，图片还原，标注为模拟）；从 xiaohu-wechat-format 批量导入 85 套主题（JSON→`#wemd` CSS 适配器，`xh_` 前缀，总 98 套，主题=数据不搬引擎）；`draft-batch` CLI + `POST /wechat/drafts/batch`（draft-only，单篇失败不中断，逐篇真实反馈）；XHS 图片卡片规划并入导出包（cards.json/cards.md，人工制卡，不触平台） | WeMD/xiaohu 方向落地（D15 的执行）；深色预览是编辑侧模拟而非微信精确渲染；批量只借草稿不借发布；插件系统明确不借（当前无第二个扩展点） | 微信提供官方深色渲染规范；出现第二个插件需求；需要批量发布（先重审人工审核边界） |
